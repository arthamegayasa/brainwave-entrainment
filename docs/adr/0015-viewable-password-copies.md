# ADR-015: Password Patient & Clinician buatan Admin bisa dilihat — salinan terenkripsi + catatan akses (2026-09-25)

**Context:** Clinician ingin selalu bisa memberi tahu Patient password-nya, termasuk password yang diganti Patient sendiri; Admin menginginkan hal yang sama untuk Clinician yang ia buat. Supabase Auth hanya menyimpan hash satu arah; tidak ada yang bisa membacanya kembali.
**Decision:** Selain hash di Auth, simpan salinan password yang terenkripsi dan hanya didekripsi di server: password Patient untuk Clinician pemiliknya dan Admin; password Clinician buatan Admin untuk Admin. Password Patient yang juga Clinician hanya bisa dilihat dan di-reset Admin, supaya satu Clinician tidak bisa masuk sebagai Clinician lain (dan data Patient-nya). Salinan dihapus saat Link diputus. Setiap kali password ditampilkan, tercatat siapa, kapan, dan milik siapa; Admin bisa membaca catatan itu. Satu baris kecil di bawah kolom password baru menyebut bahwa password itu bisa dilihat (tanpa popup), dan kebijakan privasi menjelaskannya.
**Considered Options:** Password hanya terlihat sekali saat dibuat atau di-reset, lalu tinggal hash (direkomendasikan untuk Patient dan Clinician, ditolak user): Clinician/Admin tidak bisa melihat password yang diganti pemilik akun sendiri.
**Consequences:** Kebocoran database beserta kuncinya, bug akses, atau satu Clinician berniat buruk membuka password apa adanya, termasuk password Clinician yang bisa membuka data puluhan Patient; karena orang memakai ulang password, dampaknya keluar dari SwaraSanti (email, bank). Kunci enkripsi wajib disimpan di luar database. Catatan akses menjadi satu-satunya cara mendeteksi penyalahgunaan. Menambah beban kepatuhan UU PDP di atas Listening History.
**Status:** Accepted (keputusan user, grilling 2026-09-25).
