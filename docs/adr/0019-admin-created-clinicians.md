# ADR-019: Clinician buatan Admin — asal role, login password lewat salinan password, batas Patient (2026-09-26)

**Context:** ADR-014 menetapkan bahwa role Clinician mencatat asalnya (langganan atau pemberian Admin) dan bahwa webhook pembayaran hanya menyentuh Clinician langganan. Saat Admin mulai membuat dan mempromosikan Clinician (#14), empat hal belum diputuskan: bagaimana Clinician buatan Admin login dari homepage (`resolve-login` menjawab "magic link" untuk setiap email asli), bagaimana User yang dipromosikan login, sejauh mana Admin boleh mengubah batas Patient, dan apa yang terjadi pada asal role saat webhook menurunkan seseorang.
**Decision:** (1) Sebuah email mendapat langkah password bila akunnya menyimpan salinan password (`password_login_email`, 0014). Setiap Clinician buatan Admin punya salinan sejak dibuat, jadi langsung login dengan email + password; User yang dipromosikan Admin, termasuk arthamegayasa@gmail.com, tetap memakai magic link sampai Admin me-reset password-nya sekali. (2) Admin mengisi batas Patient berupa bilangan bulat dari jumlah Patient Clinician itu saat ini sampai 1000: salah ketik bisa dibetulkan, tapi batas tidak pernah di bawah Patient yang sudah ada. (3) Form "+ Create clinician" meminta nama (wajib), email, dan password (ketik atau Generate); email yang sudah terdaftar ditolak dan Admin mempromosikan User itu. (4) "Make clinician" tersedia untuk setiap User tanpa role Clinician (Regular, Patient, Inactive Clinician), tidak pernah untuk Admin. Webhook yang menurunkan Clinician langganan juga menghapus asal role-nya (tanpa role, tanpa asal). Saat rilis, Clinician dengan langganan clinician berstatus `active` menjadi "subscription", sisanya "admin".
**Considered Options:** Semua Clinician pemberian Admin langsung mendapat langkah password (ditolak: User yang dipromosikan tanpa password terkunci dari magic link sampai Admin me-reset). Batas Patient hanya boleh naik (ditolak: salah ketik tidak bisa dibetulkan). Form tanpa nama (ditolak: tab Admin menampilkan nama).
**Consequences:** Keputusan role setelah pembayaran ada di modul Account rules (`clinicianRoleAfterPayment`) dan diuji Vitest; webhook hanya menulis hasilnya, dan hanya bila role yang dibacanya belum berubah. Promosi, batas Patient, dan pembuatan Clinician berjalan di edge function `promote-clinician`, `set-patient-limit`, dan `create-clinician` yang memutuskan izin lewat Account rules; `complete_new_clinician()` (0014) memberi role dan menyimpan salinan password dalam satu transaksi. Clinician dengan langganan `pending` saat rilis ikut menjadi "admin".
**Status:** Accepted (keputusan owner lewat koordinator, implemented #14).
