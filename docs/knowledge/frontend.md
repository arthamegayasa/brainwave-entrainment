# Frontend

Gotcha React, CSS, dan PWA di `src/ui/` dan `src/state/`.

## State & sinkronisasi

- **Dua permukaan UI yang memutasi data yang sama** (Account sheet vs Library untuk koneksi klinisi): sheet overlay tidak meng-unmount view di bawahnya — sinkronkan via `window.dispatchEvent(new Event("serenade:clinician-changed"))` + listener yang mem-bump dependency effect. Pola ringan tanpa store global. Contoh ini sudah tidak ada sejak #9: Patient tidak lagi memutus Link sendiri, dan Clinician-nya kini dibaca `useEntitlement` (`link`).

## Laporan Listening History

- **Zona waktu laporan = zona Play terbaru**, bukan zona perangkat viewer; zona yang tidak dikenal browser dilewati. Label WIB/WITA/WIT dari tabel tetap, zona lain memakai nama pendek Intl (mis. `GMT+9`).
- **Chromium en-GB menulis September sebagai "Sept"** (ICU baru), bukan "Sep" seperti di prototype.
- **Level heading laporan mengikuti tempatnya**: `headingLevel` 4 di Account (di bawah `h3` "Your listening"), 5 di Dashboard (di bawah `h4` "Listening history" dari `.detail-block`). Gaya judul kartu disatukan lewat `.lr .lr-card-title`, jadi `.detail-block h4` tidak mengenainya.
- **Laporan yang terbuka memuat ulang sendiri**: setiap 5 menit dan saat tab kembali terlihat (aturan state berbasis waktu di `CODING_STANDARDS.md`), sehingga "hari ini" berganti lewat tengah malam; reload yang gagal mempertahankan laporan yang sudah tampil.

## CSS

- **CSS grid `1fr` = `minmax(auto, 1fr)`**: min-content kartu berharga panjang memeras kolom lain. Kolom sama rata butuh `minmax(0, 1fr)` — dan konten yang tadinya "mendorong" kolom (harga coret + harga) harus bisa wrap, kalau tidak ia meluber.
- **Container query tidak bisa menata container-nya sendiri**: `@container` hanya berlaku untuk turunan. Prototype menaruh `--lh-a-cell-h` di `.lh-a` (container itu sendiri) di dalam query, sehingga tidak pernah berlaku. Di `.lr` variabel tinggi sel heatmap ditaruh di `.lr-heat` (turunan).
- **Card rows di container query**: `.roster-table td { display: block }` (0,1,1) mengalahkan `.roster-c-plays { display: none }` (0,1,0) di query yang sama — sembunyikan kolom dengan `.roster-table .roster-c-…`. Prototype punya bug yang sama.
- **Drawer di atas notifikasi**: drawer di-portal ke `#root` (z-index 90 di stacking context `#root`), jadi notifikasi Dashboard (`.dash-notice`, fixed, z 95) tetap terlihat saat drawer terbuka.

## Setup sheets

- **The Preset setup sheet fits 390×844 without scrolling**: durations on the segmented `DurationRow` (shared with the Library's duration sheet; buttons show `15`…`∞`, accessible names stay `15 min`…`∞`), Listening mode cards that keep name and sentence on one line down to 360 px (longer sentences wrap under the name, so keep them short), and Ambient as one row of icons with the chosen name beside the field label (`src/ui/ambients.ts`, whose names the Player's Ambient sheet shows as chips). The eight icons shrink from 3rem (`flex: 0 1 3rem`, `aspect-ratio: 1`) to share that row on a 360 px phone. `.setup-sheet` is a flex column: only `.setup-body` scrolls, on screens too short for it, and `.setup-foot` (Start, the Download MP3 link, Cancel) stays at the bottom above `env(safe-area-inset-bottom)`.

## Studio

- **Layout**: a hero with the session name (the editable title, `Session name`) over the picked Scene's painting, a pinned session bar (Save plus the preview transport; `.builder-transport` keeps Play, Stop, and Tap to resume), then numbered steps: Beat, Layers, Scene, Save & share. The Scene picker's legend is visually hidden there (the step heading replaces it; the group's accessible name stays "Scene"), and on phones each Scene group is one horizontally scrolling row.
- **Step 1 is the Main Beat, then its Journey**: the Main Beat card picks the entrainment type first (Binaural, Isochronic, Monaural buttons, not the grouped type menu), then Follow journey or Fixed, then Carrier and Volume. The Journey editor shows only while some entrainment layer follows it (`followsJourney`): a fixed Main Beat hides it unless another layer still follows, and then it says which. Without an entrainment layer, step 1 offers one button per type. `mainFirst` (`Builder.tsx`) moves the first entrainment layer to the front on every layer change and load so it is always Layer 1; only the display order changes, since layers mix in parallel and entrainment layers keep their order among themselves (the Player's frequency details list them in that order).
- **The Journey chart draws `journeySchedule`** (`src/audio/builder.ts`) through `beatPath`, the straight pieces the engine plays, so eased moves, the Hold, and a short preview running the moves faster (ADR-028) all show as they sound. The line and stripes take their colours from `BAND_FLOORS` (`bands.ts`), the same edges `bandForHz` uses. Chart points are numbered like their cards; a Hz label that would sit on the one before it is dropped. Preview length is only for the preview: Custom Audio stores no duration, and listeners pick one when they Play it. The Studio's Journey container is `.studio-journey`: `.journey` belongs to Home's goal strip, which is later in `App.css` and used to override the Studio card.
- **Dragging Journey points** (`JourneyChart`, `retimePoint` in `builder.ts`): each chart point is a `role="slider"` named "Start on the chart", "Point N on the chart"; they sit outside the `role="img"` SVG, whose children would be presentational. The Start and a timed closing's last point move up and down only (the closing's last point sits on the end); every other point also moves along the time, snapping to 0.1 Hz and half minutes. The points around a dragged point stay put: the move after it gives or takes the time, except after the Hold point, where the Hold does and stops at its end. While a point is dragged the chart freezes its Hz top and time span, otherwise dragging a point higher or later would rescale the chart under the pointer; the dragged point shows "Hz · min". Arrow keys do the same: up and down 0.1 Hz (Shift 1 Hz), left and right half a minute. The left axis shows Hz every 1, 2, 5, or 10 Hz with faint grid lines, band names beside them.
- **A running preview takes layer edits live but not journey edits**: `BuilderEngine` re-tunes layers in place, while the Journey and length were fixed at `start()`. Step 1 shows "Restart preview" until they match again. Loading or importing a session stops the preview, which would otherwise keep playing the old layers under the new ones.
- **`RangeField` (`StudioField.tsx`)**: Hz sliders are logarithmic, so arrow keys step in value space (near the bottom one slider position is smaller than the 0.1 Hz rounding step and the key would do nothing). A typed value commits only while it is in range and is clamped on blur, so "1" on the way to "120" never reaches the audio.
- **Empty and full sessions**: `sanitizeSession` rejects a session without layers, so with none Play, Save, Export, and Save to Audio Bank are disabled (Save used to flash "Saved ✓" for a session the list then dropped). The Add palette stops at `MAX_LAYERS` (12), which the sanitizer would otherwise cut silently.

## Player

- At widths up to 760 px, `.shell-player` owns one `100dvh` viewport with safe-area padding; only its top navigation and footer disappear. The Scene flexes to the space left after the header, 40 px Beat curve, phase, and transport. Desktop retains the usual shell.
- The Player's Ambient, Mixer, and frequency details share the existing `.sheet-backdrop`/`.sheet` bottom-sheet pattern. Frequency values read from Now Playing: Headphones left = Carrier, right = Carrier + live Beat; Speaker tone = Carrier, pulse = live Beat. ⌄ shrinks the Player into the Mini-player.
- **Custom Audio in the Player**: Library Play (Custom Audio or a saved Studio session) opens a duration-only sheet (default: the last length used, Preset or not, from `lastDurationMin` in prefs; Start saves it back), then the same Player. Ambient and Mixer are hidden: the Studio designer fixed both. Frequency details show one group per entrainment layer, by type (binaural per ear, isochronic tone and pulse, monaural both tones), numbered when a type repeats, with the layer's fixed Beat or the live ramp Beat; a Preset's Headphones mode renders as binaural and Speaker as isochronic through the same `BeatValues`. The emblem reads Headphones when any layer is binaural.
- **Where a Play returns** (`chosenIn` in `App.tsx`): a natural end, or a stop while the Player shows, goes to where the Play was chosen: Sessions for a Preset, the Library for Custom Audio and saved sessions, with the completion card there when Now Playing credited it. The desktop nav marks the same tab while the Player shows. A stop elsewhere (another Play taking over, deleting the playing saved session, Media controls Stop while minimized) still credits the streak but changes no view. The playing Library row shows "Playing" and opens the Player; it has no Stop and never restarts the Play.
- Keep screen on is opt-in per mounted Player. The Screen Wake Lock is released on User pause, device hold, hidden page, and Player unmount (including End session); a visible playing page requests it again. Browsers without the API show an unavailable message rather than blocking audio.
- The 6-second controls fade uses wall-clock inactivity only for UI, never for Play duration; the timer remains dimmed. Pausing, a device hold, or keyboard focus restores controls. The ⋯ menu closes on outside tap or after toggling Keep screen on, so it cannot pin the controls awake.

## Mini-player & Back

- **Mini-player** (`src/ui/MiniPlayer.tsx`) renders in the app shell while Now Playing has a Play and the view is neither `player` nor `landing`, at every width, fixed above `env(safe-area-inset-bottom)`. `.shell-mini-player` adds `--mini-player-clearance` to the shell's bottom padding so it never covers the footer, and a Dashboard notice rises by the same amount. Its Scene thumbnail is the precached 768 px painting, not an animated `SceneArt`. There is no Stop: ending a Play stays in the Player's ⋯ menu. Tapping it opens the Player for Presets and Custom Audio alike.
- **Device-held Plays have no banner any more**: the Player and the Mini-player share `PlayToggle` (`Player.tsx`), which pulses a visible "Tap to resume" while the device holds the audio. A Studio preview is not a Play, so the Studio transport shows its own Tap to resume while `isAudioBlocked()`. Landing has neither; Media controls still resume from there.
- **⌄ and Back return to the view the Player was opened from** (`playerFrom` in `App.tsx`): Sessions after a Preset Start, the Library after a Custom Audio Start or a tap on its Playing row, or wherever the Mini-player was tapped. The Sessions tab no longer jumps to the running Player; the Mini-player is the way back.
- **Page addresses and Back** (`src/ui/pages.ts`, `src/ui/backNavigation.ts`, ADR-027): `App.tsx` reads the view from `location.pathname` on load and on each Back or Forward (`subscribeAddress`), and sets the address (`goToAddress`) and the tab title whenever the page on screen changes; the Player keeps the page it was opened from. `useBackLayer(open, close)` pushes one more entry per open layer (the Player, then its sheet) at that page's address, tagged with its depth. `popstate` closes every layer deeper than the entry it lands on, so Back closes the sheet, then minimizes the Player; Back never stops the Play. A layer closed on screen (⌄, ✕, Escape, End session, natural end, a nav tab) removes its entry with one batched `history.go(-n)`, otherwise the next Back lands on a stale entry and seems to do nothing. A page address set in the same commit (a nav tab or natural end closing the Player) waits for that removal's `popstate`: pushed first, the removal would step back off the new page. Two more ways to land on a stale entry: `history.state` survives a reload or tab restore, so tags carry the page load's `performance.timeOrigin` and older ones count as depth 0; and Forward onto a closed layer's entry steps straight back off it. An address that names no page (a Personal URL left behind, a mistyped path, `/library/`) and a Clinician page redirected to the Library are replaced in place, so Back and a reload never return to them. A new page needs its path in `PAGES` and a rewrite in `vercel.json` (`tests/pages.test.ts`): `vite preview` answers every path, so E2E misses a missing rewrite. The Preset setup sheet, the Library duration sheet, and the Account sheet keep the browser's Back; the Personal URL `replaceState` only runs before a layer can open.

## Scenes

- **The Scene catalog** (`src/ui/scenes.ts`) holds every painting's `SceneSpec` for `SceneArt`, the pickable Scenes with their group (Nature or Science) and a label that names the picture (ADR-025), and the default. Presets keep their own Scene (its id is the Preset id); Landing and session-complete have specs but are not pickable. Each pickable Scene needs a 768 px and a 1536 px WebP and a `SceneSpec`; `tests/scenes.test.ts` reads the WebP headers to prove it.
- **"No Scene chosen" stays absent in stored specs.** `sanitizeSession` keeps only a pickable `sceneId` and never writes the default in, and `sceneOf(spec)` resolves the default wherever a Scene shows: Library rows, the Player, the Mini-player, Media controls, and the Studio preview. Specs are re-saved from their sanitized copy (every `saveCustomSession` rewrites the whole local list, Change Scene rewrites the cloud spec), so a default written in would pin old Custom Audio to the default of the day. That is how #45 moved every Custom Audio without a choice from the interim Misty Peak to Brainwave Ribbons with no data change, while an explicit `deep-meditation` stays Misty Peak. For the same reason the tile marked Default stands for "no choice" in `ScenePicker`: it shows checked while none is made, and picking it stores none again, so going back to the Default never pins it.
- **The picker lives in the Studio, above Save & Share**, so the local Save, Export, Save to Audio Bank, and Publish as template all carry it; only Clinicians and the Admin see the Studio. A Scene picked during a Studio preview updates its Media controls artwork at once. The Audio Bank edit (Dashboard) shows the same `ScenePicker` as Change Scene; Save changes rewrites the spec only when the Scene changed. Groups without Scenes are not rendered.
- Library rows show the Scene as the precached 768 px painting, like the Mini-player; only the Player animates it with `SceneArt`.
- **Adding a painting**: the generator returns a 1536×1024 PNG, but not always: one Sound to Mind variant came back 1672×941, so check the size before shipping. Ship it through Pillow as WebP (quality 80, method 6) at 1536 px and LANCZOS-resized 768 px. `SceneSpec` coordinates are the painting's own pixels: take `light` from the brightest point of a Gaussian-blurred copy (check it lands on the sun or star, since a bright cloud can win; on Mind Constellation the horizon glow won over the star), `tint` from the mean colour, and `glow` from a ring 20–140 px around the light. `SceneArt` crops to the frame's shape around a point just below `light`, moved 30% of the way toward `mist`: a wide desktop Player cuts the bottom of a painting whose light sits high (Deep Ocean's seabed; Sound to Mind's figure until its `mist` moved down to 800), and a portrait phone Player cuts the side away from the light. Smoke both widths before settling particle boxes, ray targets, and mist. Asked for a head silhouette, the model draws a facial profile, which the Science avoid-list forbids: prompt the head seen from behind.

## Build, PWA & unduhan

- **Code-split**: `React.lazy` untuk export bernama butuh `.then((m) => ({ default: m.X }))`; view di luar jalur pilih-goal-lalu-dengar + encoder lamejs (164.5 kB) dimuat saat dipakai. Chunk utama 554.7 → 338.3 kB (gzip 170 → 98.5). supabase-js masih di chunk utama karena `lib/supabase.ts` membuat client saat module load — memindahkannya butuh API client async di 7 modul `lib/`.
- **The `index-*.js` size in the build log is not the startup payload**: chunks the entry imports statically (the `useEntitlement` chunk with supabase-js, `builder`) are `modulepreload`ed alongside it, and Rolldown can merge them into `index` when the import graph changes. #42 grew `index` from 246 to 363 kB by sharing `DurationRow` with the Library, while `useEntitlement` (109 kB) and `builder` (9 kB) disappeared: startup JS went from 372 to 371 kB with two fewer requests. Compare `index` plus the preloaded chunks in `dist/index.html`.
- **Navigasi PWA ke jaringan dulu, bukan ke shell precache**: service worker menjawab setiap navigasi lewat `NetworkOnly`, jadi tab baru langsung membuka deploy terbaru; shell yang di-precache (`precacheFallback`) hanya menjawab saat jaringan gagal (offline), untuk semua URL app termasuk `/p/<username>`. `navigateFallback` dan `directoryIndex` di-`null`-kan karena keduanya menjawab navigasi dari precache lebih dulu: shell cache-first itulah yang dulu menampilkan versi lama sampai reload berikutnya. Tidak ada `networkTimeoutSeconds`: workbox-build hanya menerimanya di `NetworkFirst`, dan cache runtime `NetworkFirst` bisa menyimpan HTML deploy yang lebih baru dari precache (install SW 5,6 MB yang terputus), sehingga app rusak saat offline. Tab yang sudah terbuka tetap menjalankan kode lamanya sampai navigasi berikutnya, tanpa reload paksa yang memutus Play. File `public/` tanpa hash (ikon, `scenes/*-768.webp`) tetap datang dari precache SW lama sampai SW baru aktif: ganti nama file bila isinya berubah. Deploy pertama perubahan ini masih sekali menyajikan shell lama, karena SW lama yang menjawab navigasi itu.
- **Blob URL download**: `URL.revokeObjectURL` langsung setelah `a.click()` bisa membatalkan unduhan di Safari — tunda (60 s).
